# NIP-003: Core Morphology

## Abstract

This document defines the morphological layer of the Noe Protocol. Morphology determines how glyphs (roots) form lexical items and how operators modify those roots. The morphological layer sits below grammar (NIP-004) and above the glyph registry (NIP-002). All morphological rules produce deterministic, unambiguous structures across all modalities. Morphological resolution MUST complete before grammar applies.

## Notation Convention

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in BCP 14 [RFC 2119] [RFC 8174] when, and only when, they appear in ALL CAPITALS, as shown here.

## 1. Purpose

NIP-003 specifies the complete set of Tier-0 morphological operators, their composition rules, resolution order, and well-formedness conditions. It ensures that all morphological resolution is deterministic and complete before the grammar layer (NIP-004) applies.

## 2. Scope

### 2.1. In Scope

This NIP covers all Tier-0 morphological operators, lexical fusion and inversion, nominalization and verbalization, binder behavior, morphological resolution order, well-formedness conditions, and interaction constraints with other protocol layers.

### 2.2. Out of Scope

This NIP does not cover syntactic structure or scope (NIP-004), logical operators or semantic evaluation (NIP-005), numeric operations (NIP-007), scalar intensity operators (NIP-006), or transport-layer concerns.

## 3. Definitions

**Root:** An atomic glyph registered in `registry.json` (NIP-002). Roots do not inflect; all structure is created via morphological operators.

**Morphological Root Types:**

| Type | Description | Examples |
|------|-------------|----------|
| Entity (E) | Entities, objects, beings | dai, hum, lok |
| Quality (Q) | States, properties, valence | fel, zar, dar |
| Action (A) | Acts or processes | kra, noq |

Note: The E/Q/A typology is an informal simplification used for illustration in this NIP. The authoritative domain classification is defined in `registry.json` (NIP-002), which uses a finer-grained set of domains (D_struct, D_e, D_s, D_action, D_logic, D_temporal, D_spatial, D_epistemic, D_normative, D_quantifier, D_scalar, D_demonstrative, D_numeric, D_morph, D_morphology, D_question, D_delivery). Morphological rules apply based on the registry domain of the operand.

**Lexical Item:** A token produced by morphological resolution. Lexical items are the input to the grammar layer.

**Fusion:** The composition of two roots into a single lexical item via the fusion operator (·).

**Inversion:** The derivation of a conceptual inverse or antonym via the inversion suffix (·nei / ·𐌟).

**Morphological Operator:** A Tier-0 operator that transforms roots into lexical items before grammar applies. The complete set is: fusion (·), binder (ko), verbalizer (mek), concrete nominalizer (tok), abstract nominalizer (al), and inversion (·nei). Morphological operators belong to domain D_morph in `registry.json` and are distinct from syntactic operators (NIP-004), which create phrase structure.

## 4. Specification

### 4.1. Morphological Operators (Canonical Set)

The Tier-0 morphological operators are:

| Operator | Function | Notes |
|----------|----------|-------|
| · | Lexical fusion | Combines two roots into one lexical item |
| ko | Binder | Contextual modifier; shallow morphology |
| mek | Verbalizer / causative | Converts a root into an action |
| tok | Concrete nominalizer | Creates discrete concrete entities |
| al | Abstract nominalizer | Creates abstract concepts or event-types |
| ·nei (·𐌟) | Inversion | Creates lexical inverses or antonyms |

The inversion operator MUST NOT appear freestanding; `nei` alone is never a valid token.

### 4.2. Lexical Fusion (·)

Fusion creates an inherent fused concept from two roots.

**Form:** `X·Y`

**Rules:**

- Fusion MUST form one lexical item.
- Fusion MUST NOT encode temporary or contextual relationships.
- Fusion MUST NOT include syntactic operators (e.g., ko, nai).
- Fusion resolves before grammar.

In spoken and subvocalized contexts, the fusion joiner `·` is realized as a click — a brief alveolar click produced by the tongue touching the upper palate and releasing. This produces a short, percussive boundary marker that is phonemically distinct from all vowel and consonant phonemes used by Noe glyphs. For example, `fel·hum` is spoken as "fel-[click]-hum." The click signals that the two roots form a single fused lexical item rather than a sequence of separate tokens. In haptic and BCI modalities, the fusion boundary MUST be represented by a distinct tactile or neural marker equivalent in function to the spoken click.

**Valid:**

```noe
fel·hum
vis·lok
```

**Invalid:**

```noe
X·nai          ; syntactic operator inside fusion
root·nei·nei   ; double inversion
root·ko·root   ; binder inside fusion
```

### 4.3. Binder (ko)

The binder expresses contextual, non-inherent modification ("Y with property X").

**Form:** `X ko Y`

**Rules:**

- ko MUST NOT appear inside fusion.
- ko MUST NOT change lexical class.
- ko is a shallow morphological operator that resolves entirely at the morphology layer. After resolution, `X ko Y` produces a single modified token `Modified(Y, X)` that is emitted to the grammar layer as an opaque `IDENT`. The grammar (NIP-004) never sees `ko` as a token; it is consumed during morphological resolution.

**Valid:**

```noe
fel ko hum
zar ko lok
```

**Invalid:**

```noe
fel·ko·hum     ; ko inside fusion
```

### 4.4. Verbalizer / Causative (mek)

The verbalizer converts a root into an action: "cause/make/do X".

**Form:** `mek X`

**Rules:**

- mek denotes active production or causation.
- mek MUST NOT be bound morphologically by ko.
- mek MUST NOT take nai or ko as direct operands.

**Disambiguation:** `mek` serves two distinct roles in the protocol. As a morphological verbalizer (this section), `mek` converts a quality or entity root into the action domain during morphological resolution (e.g., `mek fel` → Action(fel)). As a syntactic action constructor (NIP-004 §4.7), `mek` appears in the grammar as a prefix operator that emits an action event (e.g., `mek @target`). The two roles are distinguished by the type of operand: morphological `mek` applies to bare roots before grammar; syntactic `mek` applies to atoms (including literals) at the grammar layer. Implementations MUST resolve morphological `mek` before the grammar layer applies.

**Valid:**

```noe
dai mek fel
dai mek zar
```

**Invalid:**

```noe
mek nai X      ; nai is a syntactic operator
mek ko X       ; ko cannot be verbalized
```

### 4.5. Concrete Nominalizer (tok)

Creates discrete, concrete entities from states or events.

**Form:** `tok X`

tok MUST NOT introduce grammatical structure. tok MUST NOT appear inside lexical compounds. After morphological resolution, `tok X` produces a single opaque `IDENT` token that the grammar layer treats as an atom. The resulting token carries type E (entity) regardless of the input root's type.

**Valid:**

```noe
tok fel
tok mek fel
```

### 4.6. Abstract Nominalizer (al)

Creates abstract concepts or event-types.

**Form:** `al X`

al MUST NOT appear inside lexical compounds. After morphological resolution, `al X` produces a single opaque `IDENT` token that the grammar layer treats as an atom. The resulting token carries type E (entity, abstract) regardless of the input root's type.

**Valid:**

```noe
al fel
al mek fel
```

### 4.7. Inversion Operator (·nei / ·𐌟)

Creates lexical conceptual inverses or antonyms.

**Form:** `X·𐌟` or `X·nei`

**Rules:**

- 𐌟 (nei) MUST NOT appear standalone.
- Double inversion (X·𐌟·𐌟) is invalid.
- nai MUST NOT appear inside compounds (nai is syntactic negation; nei is morphological inversion).
- Standalone 𐌟 MUST NOT be tokenized as a root or operator.

**Behavior:**

*Case 1 — Antonym Registered:* If `registry.json` defines an antonym mapping for X, then `X·nei` resolves to the registered antonym Y. Y MUST preserve the type signature and semantic class of X.

*Case 2 — No Antonym Registered:* If no antonym mapping exists, `X·nei` denotes InverseConcept(X) in the same semantic class.

**Valid:**

```noe
fel·𐌟         ; or: fel·nei
zar·𐌟         ; or: zar·nei
```

**Invalid:**

```noe
𐌟 X           ; standalone inversion
nei X          ; standalone inversion
X·𐌟·𐌟        ; double inversion
X·nai          ; syntactic negation inside compound
```

### 4.8. Morphological Resolution Order

Morphology MUST resolve in the following order:

1. Fusion (·)
2. Inversion (·nei)
3. Nominalizers (tok, al)
4. Verbalizer (mek)

After all morphological resolution is complete, the resulting token stream is passed to the grammar layer (NIP-004). Intensity operators (' " °) defined in NIP-006 are syntactic modifiers that attach at the grammar layer's atom production rule, not part of the morphological pipeline. They MUST NOT be applied until morphological resolution is complete.

**Example resolution:**

Input: `nai fel·𐌟 ko hum`

1. Fusion/inversion: `fel·𐌟` resolves to the inverse of fel.
2. Binder: `(fel·𐌟) ko hum` creates the modified form.
3. Grammar applies unary negation: `nai (fel·𐌟 ko hum)`.

### 4.9. Well-Formedness Conditions

The following constraints MUST be enforced:

- ko MUST NOT appear inside fusion.
- 𐌟 (nei) MUST NOT appear freestanding.
- nai MUST NOT appear inside compounds.
- tok and al MUST NOT appear inside compounds.
- mek MUST NOT be bound morphologically by ko.
- Intensity operators MUST NOT appear inside lexical fusion.
- Morphological operators MUST NOT introduce logical, temporal, or conditional scope.
- Roots MUST remain atomic; concatenation occurs only via explicit operators.

## 5. Rationale

Noe morphology is intentionally minimal, deterministic, and composable. Its purpose is to define only the essential transformations required for symbolic cognition, agents, and BCI systems. The strict separation between morphological operators (which create lexical items) and syntactic operators (which create phrase structure) prevents ambiguity at the grammar layer. The fixed resolution order ensures that all evaluators produce identical token streams from identical input, which is necessary for the determinism guarantee in NIP-005 Section 7.

More elaborate derivational morphology (aspect, modality, voice) is intentionally excluded and MAY be defined in later NIPs if justified.

## 6. Examples

### 6.1. Fusion

```noe
fel·hum        ; inherent concept: "human-feeling"
; Resolution: one lexical item FusedConcept(fel, hum) of type Q
```

### 6.2. Binder

```noe
fel ko hum     ; contextual: "human with feeling"
; Resolution: Modified(hum, fel) — hum retains its type E; fel is a modifier
```

### 6.3. Verbalizer

```noe
dai mek fel    ; "agent causes feeling"
; Resolution: mek converts fel (type Q) to action domain → Action(fel); dai is the agent
```

### 6.4. Nominalizers

```noe
tok vis        ; concrete perceptual entity
; Resolution: tok converts vis (type Q) to type E (concrete entity)

al mek fel     ; abstract concept of causing feeling
; Resolution: al converts Action(fel) to type E (abstract entity)
```

### 6.5. Inversion

```noe
fel·𐌟          ; antonym of fel (or: fel·nei)
; Resolution: if registry defines antonym for fel, resolves to that glyph;
;             otherwise InverseConcept(fel) in the same semantic class (D_s)
```

### 6.6. Combined

```noe
nai fel·𐌟 ko hum   ; negation of (inverse-feeling attributed to human)
; Step 1: fel·𐌟 resolves to InverseConcept(fel) [fusion/inversion stage]
; Step 2: InverseConcept(fel) ko hum → Modified(hum, InverseConcept(fel)) [binder stage]
; Step 3: nai applies at grammar layer → Negation(Modified(hum, InverseConcept(fel)))
```

## 7. Conformance Requirements

An implementation conforms to NIP-003 if and only if:

1. All morphological operators resolve in the order specified in Section 4.8.
2. nei NEVER appears as a freestanding token.
3. ko NEVER appears inside lexical fusion.
4. nai NEVER appears inside fused or compound forms.
5. tok and al NEVER appear inside lexical compounds.
6. Intensity operators NEVER appear inside fusion and attach only at the morphological surface.
7. All compounds (X·Y, X·nei) resolve before grammar.
8. Antonym mappings from `registry.json` are respected exactly.
9. No morphological rule introduces implicit scope or logical structure.
10. Invalid forms are rejected deterministically.

## 8. Backwards Compatibility

This NIP preserves full compatibility with earlier Noe morphology drafts. No operator semantics have changed. No glyph meanings have been redefined. All previously valid morphological forms remain valid. Future modifications MUST be strictly additive and MUST NOT break existing forms.

## 9. Security and Safety Considerations

Incorrect morphological resolution can cause evaluator divergence, semantic drift, invalid antonym resolution, malformed compounds, and grammar-layer corruption. Implementations MUST enforce deterministic resolution order, reject malformed compounds, validate operator placement, and prevent freestanding-nei, freestanding-compound, or nested-inversion errors. Morphology MUST be stable even under noisy or adversarial inputs, including BCI-decoded signals.
