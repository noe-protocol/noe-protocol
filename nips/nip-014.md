# NIP-014: Deixis Semantics

## Abstract

Deixis in Noe must be deterministic, context-grounded, and reproducible across agents. This NIP defines the semantics for **dia** ("this", proximal referent) and **doq** ("that", distal referent), and integrates these demonstratives with Tier-1 directional primitives: **rai** (right-of), **lef** (left-of), **sup** (vertical-positive), **bel** (vertical-negative), **fai** (front-of), and **ban** (behind).

Directional operators supply deterministic spatial constraints that must all be satisfied. Ambiguity resolves to undefined; undefined propagates to non-execution. This NIP completes Tier-1 referential grounding for Noe interpreters.

- **R** denotes a resolved entity reference

## 1. Purpose

NIP-014 establishes deterministic deixis resolution to ensure:

1. **No implicit referent inference** — agents never invent or guess referents absent from context
2. **LLM transparency** — proposers cannot fabricate referents; all choices are auditable
3. **Identical multi-agent resolution** — all agents resolve demonstratives identically using C_safe
4. **Deterministic spatial grounding** — spatial constraints resolve uniquely or fail deterministically
5. **Compatibility with safety projection** — deixis respects π_safe projection and C_local shards per NIP-009

## 3. Definitions

### 3.1 Demonstrative Operators

- **dia** — proximal demonstrative, Tier-1, entity-valued
- **doq** — distal demonstrative, Tier-1, entity-valued

Both evaluate to **entities**, never booleans. Resolution fails (→ undefined) if no unique determinate referent exists.

### 3.2 Candidate Structure

Sensor or perception modules populate C_local.demonstratives via deterministic input adapters (see NIP-009 §6.0). Such adapters MUST NOT fabricate grounding; if input data are missing or stale, adapter output MUST be undefined. Adapter policies MUST be recorded for audit replay (NIP-010 §4).

The demonstrative candidate structure is:

```
C_local.demonstratives = [
  {
    "id": <entity_id>,
    "region": <spatial_location>,
    "distance_m": <float>,
    "frame": <frame_id>
  },
  ...
]
```

Each candidate has:

- **id** — entity identifier that must exist in C_safe.entities
- **region** — symbolic location (e.g., "room_A", "table_top")
- **distance_m** — radial distance from speaker in meters (used for radial filtering and nearest selection)
- **frame** — coordinate frame identifier for validation

Entity positions for directional filtering are resolved separately via the three-layer position lookup (see §4.2 Step 2 and Appendix B), not carried on the candidate record itself. This separation allows the same entity to have position data from different sources (local sensors, spatial frames, entity registry) without duplicating coordinates in the candidate list.

Additionally, `C_local.demonstratives` MAY contain direct bindings for specific demonstratives:

```
C_local.demonstratives.dia = { "entity": <entity_id> }
C_local.demonstratives.doq = { "entity": <entity_id> }
```

When a direct binding is present, it takes priority over spatial resolution (see §4.2 Step 0).

### 3.3 Speaker Coordinates

Speaker location is located at:

```
C_local.speaker.location
```

Missing speaker location → undefined.

### 3.4 Distance Thresholds

Proximal and distal thresholds are provided in `C_domain.spatial.thresholds` (via Domain Pack, NIP-013):

```
thresholds.near : float   // maximum distance for proximal (dia)
thresholds.far  : float   // minimum distance for distal (doq)
```

These correspond to NIP-013's `proximal_threshold_m` and `distal_threshold_m` respectively. Missing thresholds → undefined. Default values MAY be specified by domain pack.

## 4. Specification

### 4.1 Demonstrative Semantics

For P ∈ {dia, doq}:

```
V(P, C_safe) = R        if R is unique, determinate entity
V(P, C_safe) = undefined otherwise
```

Undefined propagates per NIP-005 §3.2.

### 4.2 Deterministic Resolution Algorithm

Resolution proceeds through up to five steps. The algorithm MUST be followed in order; early termination occurs at any step that produces a definite result or undefined.

Let S = speaker location (from `C_local.speaker.location`).
Let D = demonstrative candidates (from `C_local.demonstratives`).

If S is missing → undefined. If D is missing or empty → proceed to Step 0 (direct binding may still succeed).

#### Step 0: Direct Binding (Priority Path)

If `C_local.demonstratives.{P}` contains an explicit entity binding (where P is `dia` or `doq`), the runtime MUST use it directly:

```
if C_local.demonstratives.P exists and C_local.demonstratives.P.entity is defined:
  resolved_id ← C_local.demonstratives.P.entity
  if resolved_id ∈ C_safe.entities:
    return resolved_id
  else:
    return undefined  // entity binding violation
```

Direct binding allows perception systems to resolve demonstratives externally and pass the result to Noe. If no direct binding exists, proceed to Step 1.

#### Step 1: Radial Filtering

Radial filtering selects candidates based on distance from the speaker relative to configured thresholds. Thresholds MUST be present in `C_domain.spatial.thresholds` (via Domain Pack, NIP-013); missing thresholds → undefined.

```
if P == dia:
  candidates ← { r ∈ D | r.distance_m ≤ thresholds.near }
else if P == doq:
  candidates ← { r ∈ D | r.distance_m ≥ thresholds.far }
```

If candidates is empty → undefined.

#### Step 2: Directional Filtering

If the expression chain includes directional operators (rai, lef, sup, bel, fai, ban), they act as conjunctive filters on the candidate set. Directional operators use **axis-aligned Cartesian comparisons** on entity positions (see Appendix B for the complete axis mapping):

```
for each directional operator O in chain:
  candidates ← { r ∈ candidates | axis_test(O, r.position, reference.position) }
  if candidates is empty:
    return undefined
```

Each directional operator compares the candidate's (x, y, z) coordinates against a reference position. Missing position coordinates for any candidate under directional filtering → undefined.

All directional operators in the chain MUST be satisfied conjunctively. Contradictory constraints (e.g., `rai lef`) naturally produce an empty candidate set → undefined.

#### Step 3: Unique Nearest Selection

Among remaining candidates, select the closest by distance:

```
min_distance ← min(r.distance_m for r in candidates)
nearest ← { r ∈ candidates | r.distance_m == min_distance }

if |nearest| > 1:
  return undefined  // tie — ambiguous referent
if |nearest| == 0:
  return undefined  // should not occur after Step 1

resolved ← nearest[0]
```

Ties MUST produce undefined. No tie-breaking heuristic is permitted.

#### Step 4: Entity Binding Validation

The resolved candidate's identifier MUST exist in `C_safe.entities`:

```
if resolved.id ∉ C_safe.entities:
  return undefined  // entity not in scope
```

This prevents fabricated or out-of-scope referents from entering evaluation.

#### Step 5: Result

If all steps succeed, return `resolved.id` as the entity value. The resolved entity is the value of the demonstrative expression.

## 5. Rationale

### 5.1 Radial Thresholds and Deixis Semantics

Proximal and distal demonstratives are fundamentally distance-based. The terms "this" and "that" map to speaker-relative spatial regions defined by thresholds. This separation is:

- **Linguistically grounded** — all natural languages with proximal/distal distinctions use distance thresholds
- **Deterministic** — no heuristics or ambiguity; membership is computed from numeric distance
- **Auditable** — threshold values are context data, not hidden parameters
- **Safe** — undefined on threshold misconfiguration prevents silent fallback to guessing

### 5.2 Entity Binding and Non-Fabrication

Demonstratives MUST resolve to identifiers already in C.entities. This prevents:

- **Hallucination** — an adapter or proposer inventing a new entity not in scope
- **Scope creep** — referents appearing only in dialogue, not in world state
- **Disagreement** — agents selecting different referents not grounded in shared entity data

### 5.3 Directional Constraints as Filters

Spatial operators (rai, lef, sup, bel, fai, ban) are applied *after* radial filtering. They are deterministic filters, not probabilistic scoring functions:

- **Filter semantics** — an operator either includes or excludes a candidate based on geometric relation
- **No weighting** — no candidate is "more right" than another; spatial relations are binary
- **Conjunctive** — all directional constraints must be satisfied or the result is undefined

This maintains strict determinism without approximation.

### 5.4 Unique Nearest Selection

Among remaining candidates after radial and directional filtering, the closest candidate by distance is selected. Ties → undefined. This is:

- **Deterministic** — distance is a total order; no arbitrary choice among equals
- **Predictable** — same context always yields same resolution
- **Conservative** — tie-breaking error is reported, not silently resolved
- **Auditable** — distance data are observable

### 5.5 Safety Projection Consistency

Demonstrative resolution always uses C_safe. If π_safe removes speaker coordinates or required candidate data, the result is undefined. This:

- **Preserves privacy** — no agent sees data beyond π_safe boundary
- **Maintains determinism** — same π_safe projection always yields same result
- **Prevents silent degradation** — missing data → undefined, not fallback behavior

## 6. Examples

### 6.1 Proximal Reference

```
dia
→ nearest referent within proximal threshold
  resolved to entity id via step 1–5
```

If proximal_threshold_m = 1.5 m and candidates are at {0.8 m, 1.9 m, 3.2 m}, then dia selects the entity at 0.8 m.

### 6.2 Distal with Directional Constraint

```
rai doq
→ nearest distal referent to the right of speaker
  step 1: radial filter (distance ≥ distal_threshold_m)
  step 2: directional filter (angle in right hemisphere)
  step 3: unique nearest selection
```

### 6.3 Vertical Proximity

```
sup dia
→ nearest proximal referent above speaker
  step 1: radial filter (distance ≤ proximal_threshold_m)
  step 2: directional filter (height_m > speaker_height)
  step 3: unique nearest selection
```

### 6.4 Front-Distal

```
fai doq
→ nearest distal referent in front of speaker
  step 1: radial filter (distance ≥ distal_threshold_m)
  step 2: directional filter (sagittal: front angle region)
  step 3: unique nearest selection
```

### 6.5 Ambiguity Resolution

```
dia (with two candidates at exactly 0.8 m)
→ undefined (tie on distance)
```

### 6.6 Missing Directional Data

```
sup dia (with some candidates missing height_m field)
→ undefined (incomplete candidates cannot satisfy directional constraint)
```

### 6.7 Out-of-Scope Reference

```
dia (where resolved.id does not appear in C.entities)
→ undefined (entity binding violation)
```

### 6.8 Multi-Agent Agreement

Agent 1 and Agent 2 both evaluate `dia` with identical C_safe:
- Same speaker location
- Same candidate list
- Same thresholds
- Result: both resolve to the same entity id, or both resolve to undefined
- Disagreement is impossible given identical inputs

## 7. Conformance Requirements

A conformant Noe runtime MUST:

1. **Maintain speaker coordinates** in C_local.speaker.location at evaluation time
2. **Maintain demonstrative candidate list** in C_local.demonstratives with complete {id, region, distance_m, frame} records; entity positions MUST be resolvable via the three-layer lookup (C_local.position, C_root.spatial.frames, C_safe.entities) with numeric (x, y, z) coordinates when directional operators are used
3. **Provide proximal and distal thresholds** in C_domain or domain pack
4. **Compute directional relations** deterministically from axis-aligned Cartesian comparisons on entity positions (x, y, z)
5. **Apply π_safe projection** before demonstrative resolution
6. **Never infer or guess referents** absent from C_local.demonstratives
7. **Propagate undefined to non-execution** per NIP-005
8. **Record adapter policies** for any deterministic input adapters feeding C_local (NIP-010 §4)
9. **Validate entity binding** against C.entities for all resolved referents
10. **Handle multi-agent shards** by resolving only using matching C_safe fragments

- **No grammar changes** — dia and doq remain Tier-1 token sequences per NIP-004
- **No Tier-0 modifications** — evaluation and execution semantics per NIP-005 are unchanged

- **Existing chains remain valid** — any prior use of demonstratives in Noe code continues to function under this NIP's deterministic algorithm

## 9. Security and Safety Considerations

### 9.1 Non-Guessing

Demonstrative resolution must never guess or probabilistically choose referents:

- If ambiguous (tie on distance), result is undefined
- If multiple candidates satisfy directional filter, all are retained for Step 3; if tie remains, undefined
- No heuristic fallback, no score weighting, no "reasonable guess"

### 9.2 Threshold Boundaries

Candidates must strictly satisfy radial thresholds:

- **dia**: distance_m ≤ thresholds.near (inclusive)
- **doq**: distance_m ≥ thresholds.far (inclusive)
- Candidates exactly on boundary are included
- No "approximately" or "close to" threshold logic

### 9.3 Directional Consistency

Directional operators must all be satisfied:

- If a chain specifies **rai** and **sup**, candidate must satisfy both right (x1 > x2) AND above (z1 > z2)
- Missing or non-numeric position coordinates → undefined; no partial satisfaction
- Directional conflict (e.g., specifying **rai** and **lef** simultaneously) → empty candidate set → undefined

### 9.4 Missing Data Handling

Missing required data at any step → undefined:

- Missing speaker location
- Missing demonstrative list
- Missing or non-numeric (x, y, z) coordinates for candidates in directional filter step
- Missing thresholds
- Missing entity in C.entities
- π_safe removing required data

### 9.5 Hard Binding to NIP-005 Safety Rules

All demonstrative evaluation is bound by NIP-005 §3 safety rules:

- Undefined propagates and prevents execution
- Agents never execute chains with undefined subexpressions
- Safety projection π_safe is applied before resolution
- Multi-agent disagreement triggers non-execution

## Appendix A: Resolution Steps in Pseudocode

```
function resolve_demonstrative(P, C_safe):
  // Step 0: Direct binding (priority path)
  binding ← C_local.demonstratives[P]
  if binding is not null and binding.entity is defined:
    if binding.entity ∈ C_safe.entities:
      return binding.entity
    else:
      return undefined  // entity binding violation

  // Spatial fallback path
  S ← C_local.speaker.location
  D ← C_local.demonstratives  // candidate list

  if S is null or D is empty:
    return undefined

  thresholds ← C_domain.spatial.thresholds
  if thresholds is null:
    return undefined

  // Step 1: Radial filtering
  if P == dia:
    candidates ← { r ∈ D | r.distance_m ≤ thresholds.near }
  else if P == doq:
    candidates ← { r ∈ D | r.distance_m ≥ thresholds.far }

  if candidates is empty:
    return undefined

  // Step 2: Directional filtering (if chain includes spatial operators)
  if chain.has_directional_operators():
    for each operator O in chain.directional_operators:
      ref ← resolve_position(reference_entity)
      candidates ← { r ∈ candidates |
        pos ← resolve_position(r.id)
        axis_test(O, pos, ref) == true
      }
      if candidates is empty:
        return undefined

  // Step 3: Unique nearest selection
  min_distance ← min(r.distance_m for r in candidates)
  nearest ← { r ∈ candidates | r.distance_m == min_distance }

  if |nearest| > 1:
    return undefined  // tie — ambiguous referent

  resolved ← nearest[0]

  // Step 4: Entity binding validation
  if resolved.id ∉ C_safe.entities:
    return undefined

  return resolved.id


function resolve_position(entity_id):
  // Three-layer lookup (first match wins)
  if C_local.position[entity_id] exists:
    return C_local.position[entity_id]  // {x, y, z}
  if C_root.spatial.frames[entity_id] exists:
    return C_root.spatial.frames[entity_id]
  if C_safe.entities[entity_id].position exists:
    return C_safe.entities[entity_id].position
  return undefined


function axis_test(operator, pos1, pos2):
  // Axis-aligned Cartesian comparison
  match operator:
    lef → return pos1.x < pos2.x
    rai → return pos1.x > pos2.x
    fai → return pos1.y > pos2.y
    ban → return pos1.y < pos2.y
    sup → return pos1.z > pos2.z
    bel → return pos1.z < pos2.z
```

## Appendix B: Directional Filter Specification

Directional filters use **axis-aligned Cartesian comparisons** on entity positions. Given candidate position `(x1, y1, z1)` and reference position `(x2, y2, z2)`, the six operators test:

| Operator | Axis | Condition | Meaning |
|----------|------|-----------|---------|
| **lef** | X | x1 < x2 | Candidate is to the left of reference |
| **rai** | X | x1 > x2 | Candidate is to the right of reference |
| **fai** | Y | y1 > y2 | Candidate is in front of reference |
| **ban** | Y | y1 < y2 | Candidate is behind reference |
| **sup** | Z | z1 > z2 | Candidate is above reference |
| **bel** | Z | z1 < z2 | Candidate is below reference |

Position resolution checks three sources in order (first match wins):

1. `C_local.position.{entity_id}` → `{x, y, z}`
2. `C_root.spatial.frames.{entity_id}` → `{x, y, z}`
3. `C_safe.entities.{entity_id}.position` → `{x, y, z}`

All three coordinates (x, y, z) MUST be numeric. Missing or non-numeric coordinates for any candidate under directional filtering → undefined.

## Appendix C: Multi-Agent Consistency Proof Sketch

**Claim:** If agents A and B have identical C_safe shards, they resolve dia and doq identically.

**Proof:**
1. Both check direct binding in C_local.demonstratives.P → same binding or both absent
2. Both have S = same speaker location (from C_local.speaker.location)
3. Both have D = same candidate list (from C_local.demonstratives)
4. Both have same thresholds (from C_domain.spatial.thresholds)
5. Radial filtering depends only on {D, thresholds} → same candidate set
6. Directional filtering depends only on entity positions resolved via same three-layer lookup → same Cartesian comparisons → same filtering
7. Unique nearest selection depends only on distance_m in candidate set → same result
8. Entity binding depends only on C_safe.entities → same validation
9. **Result:** identical resolution or both undefined ∎

If C_safe differ → agents may compute different sets; disagreement is prevented by requiring matching C_safe, not by probabilistic reconciliation.
