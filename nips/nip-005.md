# NIP-005: Core Semantics

## Abstract

This document defines the model-theoretic semantics for the Noe Protocol. Every well-formed Noe chain evaluates to a truth value in T = {true, false, undefined}, an entity, state, action, event, numeric value, or undefined. Semantics are deterministic, context-explicit, side-effect-free, and evaluated exclusively against C_safe, the safe context projection defined in NIP-009. This NIP specifies the core logical meaning of all Tier-0 and Tier-1 operators, including truth-functional logic, epistemic operators, conditionals, temporal and spatial relations, action and event constructors, undefined propagation, and determinism guarantees.

This document incorporates the Determinism Patch: one glyph maps to one meaning, no operator shadowing, no contextual inference, undefined implies non-execution, epistemic operators are restricted to modal sets, all actions require guard certainty, and negation applies to propositions rather than entities or actions.

## Notation Convention

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in BCP 14 [RFC 2119] [RFC 8174] when, and only when, they appear in ALL CAPITALS, as shown here.

## 1. Purpose

NIP-005 specifies truth semantics, deterministic epistemic operators (shi, vek, sha), undefined propagation rules, temporal and spatial semantics, action and event semantics, the interaction with the safe context projection (C_safe), and the determinism guarantees that bind all conformant evaluators.

It does not define learning, heuristics, grounding, inference, or context construction. Grounding is handled by NIP-012 and NIP-013; context construction by NIP-009; validation by NIP-015; epistemic mapping by NIP-017.

## 2. Scope

### 2.1. In Scope

Truth-functional semantics, deterministic epistemics, predication, conditionals, temporal and spatial relations, action and event semantics, undefined propagation, type constraints, demonstratives and deixis, request constructors, quantifiers, and the determinism lemma.

### 2.2. Out of Scope

Learning, inference, planning, LLM reasoning, parser and morphology rules, grounding and validation (NIP-015), context sharding (NIP-009), numeric arithmetic semantics (NIP-007), and liveness/retry behavior (NIP-016).

## 3. Definitions

**Evaluation function V(P, C_safe):** The function that maps a chain P and a safe context C_safe to a semantic value.

**Truth domain T:** The set {true, false, undefined}, evaluated under Strong Kleene (K3) three-valued logic.

**Undefined:** A first-class semantic value indicating that the evaluator does not have sufficient admitted support to produce a defined value. Undefined is not false, not an error, and not an exception.

**C_safe:** The canonical evaluation context produced by the safe projection function defined in NIP-009. All evaluation in this NIP references only C_safe.

**Modal sets:** The structures C_safe.modal.knowledge, C_safe.modal.belief, and C_safe.modal.certainty, populated via calibrated evidence mapping (NIP-017).

**Semantic domains:** D_e (entities), D_s (states/qualities), D_action (actions/events), D_n (numeric values), D_spatial (spatial regions), D_temporal (temporal instants), and T (truth).

## 4. Specification

### 4.1. Semantic Universe

Noe v1.0 assumes one active world w, a temporal domain T_m, and an evaluation time t in T_m. All expressions evaluate to one of the semantic domains or undefined.

### 4.2. Context and Safe Projection

All evaluation uses the safe context:

```text
C_safe = pi_safe(C_rich)
```

The safe projection removes noise, resolves contradictions, enforces staleness, and outputs deterministic, stable epistemic and literal sets (NIP-009). All semantics in this NIP reference only C_safe. Missing required fields produce undefined.

### 4.3. Truth Domain

The truth domain is Strong Kleene (K3):

```text
T = {true, false, undefined}
```

Undefined arises from missing literals, missing context fields, unresolvable deixis, type mismatches, incompatible operator domains, or missing spatial/temporal models. Undefined MUST propagate unless an operator explicitly states otherwise (none do in this NIP).

#### 4.3.1. Undefined Taxonomy

- **Semantic undefined:** Missing literal, unresolved deixis, domain mismatch, missing spatial model.
- **Epistemic undefined:** Missing or malformed modal structure.
- **Context undefined:** Missing or stale field in C_safe.
- **Structural undefined:** Malformed chain or operator misuse.

Undefined is not used to represent epistemic ignorance. Epistemic ignorance is expressed via `nai shi P` ("it is not the case that we know P").

#### 4.3.2. Undefined Implies Non-Execution

When any chain evaluates to domain = "undefined", the evaluator MUST NOT emit actions, side effects, or delivery events. This rule is semantic and mechanical, not guidance, and MUST be enforced identically across all conformant evaluators.

### 4.4. Undefined Propagation

All truth-functional operators propagate undefined:

| Input | Output |
|-------|--------|
| true | depends on operator |
| false | depends on operator |
| undefined | undefined |

Epistemic operators (shi, vek, sha) are not generic truth-functional operators; they follow the modal membership rules in Section 4.8 and do not follow the generic propagation rule of this section.

### 4.5. Logical Operators

#### 4.5.1. nai — Negation

```text
V(nai P) = true      if V(P) = false
V(nai P) = false     if V(P) = true
V(nai P) = undefined if V(P) = undefined
```

#### 4.5.2. an — Conjunction (Strong Kleene)

| P | Q | P an Q |
|---|---|--------|
| T | T | T |
| T | F | F |
| T | U | U |
| F | T | F |
| F | F | F |
| F | U | F |
| U | T | U |
| U | F | F |
| U | U | U |

#### 4.5.3. ur — Disjunction (Strong Kleene)

| P | Q | P ur Q |
|---|---|--------|
| T | T | T |
| T | F | T |
| T | U | T |
| F | T | T |
| F | F | F |
| F | U | U |
| U | T | T |
| U | F | U |
| U | U | U |

#### 4.5.4. nex — Exclusion

nex removes an entity or proposition from the active evaluation domain. Unlike nai (which negates a truth value), nex operates on the domain itself.

```text
V(nex P) = excluded(P) if V(P) is defined
V(nex P) = undefined   if V(P) = undefined
```

In v1.0, `nex` evaluates as logical negation with scope containment: within a `sek...sek` scope, `nex P` returns `not V(P)` and the exclusion MUST NOT propagate beyond the enclosing scope boundary (cf. `registry.json` metadata: `nex_scope: "local"`). Evaluators MUST enforce local scope containment for `nex`. Full domain-level exclusion semantics (removing an entity or proposition from the active evaluation domain rather than negating its truth value) are deferred to a future NIP. The v1.0 behavior is operationally equivalent to `nai` with the additional scope containment constraint.

#### 4.5.5. Numeric Equality and Comparisons

Numeric equality (=) and comparisons (<, >, <=, >=) return truth values if both operands are in D_n, or undefined if either operand is non-numeric or undefined. Semantics are defined fully in NIP-007.

### 4.6. Literals

Literals have the form `@x`. They are canonicalized using NFKC plus lowercase and resolved only from C_safe.literals.

**Strict mode:** Missing literal produces ERR_LITERAL_MISSING. Undefined target in action produces ERR_UNDEFINED_TARGET.

**Partial mode:** Missing literal produces undefined. Undefined propagates normally.

### 4.7. Conditional — khi

The guard operator. If the guard resolves to undefined, the action MUST NOT execute (reinforcing the undefined-implies-non-execution invariant).

**Form:** `GuardExpr khi sek ActionExpr sek`

| Guard | Output |
|-------|--------|
| true | V(ActionExpr) |
| false | false |
| undefined | undefined |

If the guard is not true, the action block MUST NOT execute and no action is emitted. If ActionExpr evaluates to an action, the entire expression has domain D_action.

### 4.8. Epistemic Operators (Deterministic Membership Model)

Epistemic operators are pure membership checks over C_safe.modal. No probabilities, no inference, no factivity assumptions beyond the safe projection. Modal sets are constructed via calibrated evidence mapping (NIP-017). NIP-005 defines only how operators behave given these sets.

#### 4.8.1. shi — Knowledge

```text
V(shi @p, C_safe) = true      if @p in C_safe.modal.knowledge
V(shi @p, C_safe) = false     if @p not in C_safe.modal.knowledge
V(shi @p, C_safe) = undefined if C_safe.modal is missing
```

Ignorance ("not known") yields false, not undefined. Undefined is reserved for missing or broken modal structures.

**Negation interaction:**

- `nai shi P` = epistemic ignorance ("it is not the case that we know P"). This is the correct way to express "I don't know P".
- `shi (nai P)` = "we know not-P" — this requires positive evidence of absence and is a valid, distinct claim.

#### 4.8.2. vek — Belief

```text
V(vek @p, C_safe) = knowledge[@p]  if @p in C_safe.modal.knowledge
V(vek @p, C_safe) = belief[@p]     if @p in C_safe.modal.belief
V(vek @p, C_safe) = undefined      otherwise (including modal missing)
```

Knowledge implies belief — `vek` checks knowledge first, then belief. Membership in these sets MUST satisfy the threshold rules defined in NIP-017. Returns `undefined` (not `false`) when @p is absent from both maps, consistent with Noe's three-valued logic.

#### 4.8.3. sha — Certainty

```text
let cert = C_safe.modal.certainty[@p]        (numeric [0,1])
let threshold = C_safe.modal.certainty_threshold

V(sha @p, C_safe) = knowledge[@p] or belief[@p]  if cert >= threshold
V(sha @p, C_safe) = undefined                     if cert < threshold
V(sha @p, C_safe) = error ERR_EPISTEMIC_MISMATCH  if threshold missing (strict)
V(sha @p, C_safe) = undefined                     if modal missing
```

Unlike `vek` and `shi`, `sha` does not use boolean set membership. Instead, it reads a numeric certainty level from `C_safe.modal.certainty[@p]` and compares it against the runtime-configurable `C_safe.modal.certainty_threshold`. If the threshold is met, `sha` returns the truth value from the knowledge or belief map. In strict mode, a missing `certainty_threshold` produces `ERR_EPISTEMIC_MISMATCH`; in non-strict mode, a legacy fallback of 0.8 applies. See NIP-017 for full threshold semantics.

### 4.9. Structural Operators — el, nul

The following operators belong to the structural domain (D_struct in `registry.json`) and are not epistemic. They are placed in a separate section to avoid confusion with the epistemic membership model above.

#### 4.9.1. el — Identity

`el` is a binary structural predicate that tests value identity. Both operands are Tier-0 registered glyphs (g_el, D_struct, type_sig: Pred).

```text
V(A el B, C_safe) = true      if A and B denote the same value
V(A el B, C_safe) = false     if both defined and unequal
V(A el B, C_safe) = undefined otherwise
```

#### 4.9.2. nul — Empty / Null

`nul` is a Tier-0 structural constant (g_nul, D_struct, type_sig: Const) representing the empty or null value. `A el nul` evaluates to true if and only if A is an empty structure; false if A is a non-empty defined value; undefined if A is undefined.

### 4.10. Predication — es

Predication relates an entity to a state.

**Form:** `E es S` where E is in D_e and S is in D_s.

```text
V(E es S) = true      if S holds of E in C_safe
V(E es S) = false     if S is explicitly false of E
V(E es S) = undefined if entity/state unresolved or predication model missing
```

Predication is OPTIONAL for v1.0. If not implemented, it MUST always evaluate to undefined.

### 4.11. Actions and Events

Action constructors produce values in D_action. They are not truth-valued.

#### 4.10.1. mek — Perform

```text
V(mek X) = action(X) if X in D_action or D_s or is a literal
           undefined otherwise
```

#### 4.10.2. vus — Deliver

```text
V(vus X) in D_action
```

#### 4.10.3. vel — Receive

```text
V(vel X) in D_action
```

#### 4.10.4. men — Audit Event

```text
V(men X) in D_action
```

Also adds an audit edge (NIP-010). Audit cycles produce undefined.

#### 4.10.5. Action Misuse Constraints (Strict Mode)

The validator MUST raise ERR_ACTION_MISUSE for: mixing request construction (noq) with direct action creation without a guarding khi scope, emitting actions outside a guarded khi sek...sek idiom, or building composite action lists that include unguarded items or items with undefined targets. In partial mode, these MAY evaluate to undefined but MUST NOT emit actions.

### 4.12. Request Constructor — noq

noq constructs request actions.

**Type signature:** `noq : D_e x D_action -> D_action`

```text
V(S noq A) = req(S, A) in D_action
```

Undefined if either operand is undefined or in an incorrect domain. noq is not truth-valued; to convert to truth, wrap in kra or guards.

### 4.13. Temporal Semantics

All temporal semantics depend on C_safe.temporal (NIP-009 §4.3). If C_safe.temporal is missing, evaluation produces undefined.

**nau (present):** `V(nau P) = V(P)` — evaluates P at the current evaluation time t.

**ret (past):** True if there exists t' < t where P was true in C_safe.temporal.history; false if P was provably false for all t' < t; undefined otherwise. The temporal history model is defined in NIP-009 §4.3.

**tri (future):** True if there exists t' > t where P becomes true per C_safe.temporal.projections; false if provably never true; undefined otherwise. The temporal projection model is defined in NIP-009 §4.3.

**qer (repetition):** In v1.0, `qer` has identity semantics: `V(qer P) = V(P)`. Conformant evaluators MUST treat `qer` as returning the value of its operand unchanged. Full repetition semantics (loop count, iteration policy, execution bounds) are deferred to a future NIP. This deferral is deliberate: loop semantics interact with liveness (NIP-016) and action emission in ways that require careful specification to preserve the safety invariant.

### 4.14. Quantifiers — eni, sem, mun, fiu

Quantifiers operate on lists of evaluated truth values: `L = [V(X1), V(X2), ...]`. The quantifier principle: undefined counts as false. N = |L|.

**eni (exists):** True if any element is true; false otherwise.

**sem (for all):** True if all elements are true; false otherwise. Undefined counts as false.

**mun (many):** True if (true_count / N) >= 0.4; false otherwise. N = 0 produces undefined. The threshold 0.4 is a v1.0 design choice calibrated for intuitive alignment with natural-language "many" (roughly "more than a third"). This threshold is fixed for v1.0 and is not sourced from NIP-017 or any external calibration; future NIPs MAY introduce configurable thresholds via domain packs (NIP-015).

**fiu (few):** True if (true_count / N) <= 0.1; false otherwise. N = 0 produces undefined. The threshold 0.1 is a v1.0 design choice calibrated for intuitive alignment with natural-language "few" (roughly "one in ten or fewer"). This threshold is fixed for v1.0 and follows the same provenance as `mun`; future NIPs MAY introduce configurable thresholds.

### 4.15. Demonstratives and Deixis — dia, doq

Demonstratives refer to context-resolved entities via C_safe.demonstratives. Resolution requires C_safe.demonstratives (a list of referents with id, location, distance_to_speaker) and C_safe.spatial.thresholds (near and far).

**dia (proximal / "this"):** Select the nearest referent R such that distance(R, speaker) <= near_threshold. If exactly one, return R. If zero, return undefined. If more than one, select the nearest.

**doq (distal / "that"):** Select the first referent R such that distance(R, speaker) >= far_threshold. Same resolution rules.

After resolution, demonstratives behave like entity expressions: `dia nel @target` resolves to `nel(ResolvedReferent, target)`. Failure to resolve produces undefined. Demonstratives never produce error codes. Resolution occurs before semantic evaluation. Full deixis semantics are specified in NIP-014.

### 4.16. Spatial Semantics

Spatial operators are binary predicates that evaluate geometric relationships between entities in C_safe.spatial. All spatial operators require C_safe.spatial to be present; if it is missing, evaluation produces undefined. Entity positions are resolved from C_safe.spatial.entities, which maps entity keys to position vectors. Distance is Euclidean unless the spatial model specifies otherwise.

**nel (near):** `V(A nel B) = true` if `distance(A, B) <= C_safe.spatial.thresholds.near`; false if both positions are defined and the distance exceeds the threshold; undefined if either position or the threshold is missing.

**tel (far):** `V(A tel B) = true` if `distance(A, B) >= C_safe.spatial.thresholds.far`; false if both positions are defined and the distance is below the threshold; undefined if either position or the threshold is missing.

**xel (aligned):** `V(A xel B) = true` if the angular difference between A's orientation vector and the direction from A to B is within `C_safe.spatial.orientation.tolerance` degrees; false if both are defined and the angle exceeds tolerance; undefined if orientation or tolerance data is missing.

**tra (towards / in front):** `V(A tra B) = true` if the dot product of A's facing direction and the unit vector from A to B is greater than or equal to the cone threshold `C_safe.spatial.orientation.cos_theta` (default: 0.707, approximately 45 degrees); false otherwise; undefined if orientation data is missing.

**fra (behind / away):** `V(A fra B) = true` if the dot product of A's facing direction and the unit vector from A to B is less than or equal to the negative cone threshold; false otherwise; undefined if orientation data is missing.

**en (containment / in region):** `V(A en B) = true` if `distance(A, B) <= B.radius`, where B defines a region with a radius attribute; false if both are defined and the distance exceeds the radius; undefined if B has no radius attribute or positions are missing.

All spatial operators sit in the relational precedence band (NIP-004 §4.7, band 4). They compose with logical and temporal operators in the standard way: `ret dai nel @target` evaluates whether the speaker was near the target in the past.

### 4.17. Operator Precedence

Operator precedence is defined canonically in NIP-004 Section 4.7. All evaluators MUST apply that precedence. Unary operators are right-associative, binary operators are left-associative, and khi is non-associative.

### 4.18. Undefined vs. Error

NIP-005 defines undefined only. Errors belong to the morphology layer (NIP-003), grammar layer (NIP-004), registry (NIP-002), and validator (NIP-015).

Undefined arises from: missing literals (partial mode), unresolvable demonstratives, missing context fields, absent spatial/temporal models, type mismatches, missing modal structures, and suppressed contradictory facts.

Errors (not semantic undefined) include: malformed chains, invalid morphology, unknown glyphs, stale context (ERR_STALE_CONTEXT), and missing literals in strict mode (ERR_LITERAL_MISSING).

Undefined MUST propagate upward through truth evaluation per the K3 tables. Errors MUST halt evaluation.

### 4.19. Interaction with Safe Projection and Validator

All semantics are defined only over C_safe. The safe projection (NIP-009 Section 6) applies staleness bounds, removes contradictory sensor values, normalizes units, prunes unsafe data, and produces a coherent, deterministic context.

Epistemic operators check membership in cleaned modal sets and do not represent metaphysical truth or perform inference. The expression `nai shi @p` represents "I don't know p". Modal data MUST satisfy NIP-017 validator rules (confidence thresholds, stale-evidence checks, contradiction checks, evidence-required checks).

**Staleness enforcement:** Before semantic evaluation, if `now_ms - literal_timestamp > C_safe.temporal.max_staleness`, the validator MUST emit ERR_STALE_CONTEXT and the evaluator MUST NOT evaluate the chain.

**AST safety validation:** The validator evaluates AST safety before semantics execute. Any non-pass result MUST block execution with domain = "error". AST validation occurs prior to semantic evaluation and prior to action emission.

### 4.20. Determinism Lemma

Given a fixed `registry.json`, a fixed C_safe, and a valid chain P, all conformant evaluators MUST satisfy:

```text
V(P, C_safe) = constant
```

This follows from: unambiguous PEG grammar (NIP-004), deterministic morphology (NIP-003), deterministic safe projection (NIP-009), pure functional semantics, strict epistemic and guard rules, no inference or rewriting, and calibrated epistemic mapping (NIP-017).

#### 4.20.1. Cross-Agent Determinism Invariant

For agents A and B evaluating chain P:

**If C_safe(A) = C_safe(B):** `eval(P, C_A) = eval(P, C_B)` — identical results, always.

**If C_safe(A) != C_safe(B):** Agents MUST NOT produce contradictory actions. They may only diverge when epistemic sets differ (private literals), demonstratives resolve to different referents, one context is stale or undefined, or calibrated modal sets differ due to differing validated evidence. Divergences MUST degrade into undefined or error, never into contradictory actions.

## 5. Rationale

Noe's semantic model is deliberately restrictive. By choosing Strong Kleene three-valued logic rather than classical two-valued logic, the protocol gains a safe "I don't know" value (undefined) that prevents premature commitment. The epistemic operators (shi, vek, sha) are membership checks rather than inference engines because inference is non-deterministic across agents. The undefined-implies-non-execution invariant exists because in safety-critical systems (robotics, autonomous agents), uncertain information must never trigger physical actions. The predication model (es) is optional in v1.0 because full entity-type semantics require additional specification work that should not block the core protocol.

## 6. Examples

### 6.1. Epistemic

```noe
shi @door          ; true if @door in knowledge, false otherwise
nai shi @door      ; true if @door NOT in knowledge (epistemic ignorance)
vek @temp          ; true if @temp in belief
```

### 6.2. Conditional

```noe
shi @zone_clear khi sek mek @move sek nek
```

If zone_clear is known: executes action. If unknown: false, no action. If context missing: undefined, no action.

### 6.3. Spatial

```noe
dai nel doq
```

Resolves doq, then applies nel. Missing threshold produces undefined.

### 6.4. Request

```noe
dai noq mek vus @packet1 nek
```

Evaluates to D_action (request event).

### 6.5. Nested Guards

```noe
true khi sek true khi sek mek @halt sek sek nek
```

Action emitted only if all guards evaluate to true.

### 6.6. Missing Literal

```noe
shi @missing khi sek mek @halt sek nek
```

Strict mode: ERR_LITERAL_MISSING. Partial mode: undefined. No action in either case.

### 6.7. Introspective Reasoning

```noe
nai shi @location_known khi sek mek @request_gps sek nek
```

If location is not known, request GPS. This demonstrates the epistemic ignorance pattern.

## 7. Conformance Requirements

An implementation conforms to NIP-005 if and only if:

1. It implements all operator semantics exactly as specified in Section 4.
2. It evaluates only over C_safe.
3. It treats undefined as a first-class semantic value.
4. It never coerces undefined to true or false.
5. It implements epistemic operators as deterministic membership checks.
6. It preserves operator precedence per NIP-004 Section 4.7.
7. It produces identical output to the reference tests in NIP-011.
8. It produces identical output across agents for identical (chain, C_safe) pairs.
9. It diverges only where epistemically justified (private literals, different validated evidence).
10. It enforces the undefined-implies-non-execution invariant.

## 8. Backwards Compatibility

This NIP is the first formal specification of Noe semantics. Earlier informal semantic descriptions are superseded. The Determinism Patch is incorporated into this document. All previously valid semantic evaluations that conform to this specification remain valid. The semantics defined in Sections 4 through 5 of this document are frozen for v1.0; only bug fixes are permitted.

## 9. Security and Safety Considerations

NIP-005 enforces no heuristics, no inference, no probabilistic reasoning, no silent fallback, undefined always blocks action, the validator suppresses unsafe chains, and semantics remain deterministic across agents. These guarantees are enforced jointly by the semantics in this NIP, the validator requirements in NIP-015, the epistemic mapping rules in NIP-017, and the liveness policy constraints in NIP-016.
