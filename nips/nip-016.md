# NIP-016: Liveness Policy Layer

## Abstract

NIP-016 formalizes the Liveness Policy Layer, an external control mechanism that manages undefined and error outcomes in the Noe evaluation loop. The Liveness Policy Layer enforces recovery strategies—including retry, degraded mode, emergency stop, and escalation—while maintaining absolute commitment to Noe's core safety invariant: an undefined or error result MUST NOT yield an action under any circumstances. This specification defines the state machine, responsibilities, allowed strategies, required parameters, and conformance requirements for implementations.

## Notation Convention

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in BCP 14 [RFC 2119] [RFC 8174] when, and only when, they appear in ALL CAPITALS, as shown here.

---

## 1. Purpose

The Liveness Policy Layer exists to:

1. **Enforce the Core Safety Invariant**: Ensure that undefined or error evaluation results never directly produce actions, regardless of retry attempts, escalation states, or operational pressure.

2. **Distinguish Failure Types**: Categorize failures into epistemic undefined (insufficient grounding), context undefined (missing or stale local context), and structural error (parser/format failures) to enable targeted recovery.

3. **Manage Recovery Strategies**: Implement bounded retries, graceful degradation, emergency stops, and human escalation in a coordinated state machine.

4. **Maintain Determinism**: Preserve evaluation determinism across retry boundaries without falsifying context or altering C_rich.

5. **Enable Observability**: Log all state transitions, retry counts, and undefined rates to support auditing and offline analysis per NIP-010.

---

### 1.1 Implementation Status

> **Note**: NIP-016 specifies a normative design for the Liveness Policy Layer. The noe-gate reference implementation does NOT currently include a `NoePolicyWrapper` or liveness state machine. The pseudocode in §4.9 is illustrative of the required behavior, not a description of existing code. Implementations wishing to conform to NIP-016 must build the policy layer as an external wrapper around the core Noe evaluator.

---

## 2. Scope

This specification applies to:

- Any Noe implementation that handles undefined or error outcomes in the evaluation loop.
- External policy controllers that sit between the core Noe evaluator and downstream action executors.
- Systems requiring bounded retry logic, graceful degradation, or emergency halt capability.
- Deployments subject to undefined rate monitoring or escalation governance.

This specification does NOT mandate:

- A specific programming language or architecture.
- A particular retry backoff algorithm (e.g., exponential vs. linear).
- Real-time guarantees or specific latency bounds.
- Integration with any specific escalation platform.

---

## 3. Definitions

**Action**: A deterministic output of successful evaluation, representing a directive or state update.

**Undefined (Epistemic)**: The evaluator cannot derive an action due to insufficient grounds for decision (e.g., missing sensor data, ambiguous context).

**Undefined (Context)**: The evaluator cannot access or reconstruct C_local (local context) due to staleness, unavailability, or data loss.

**Structural Error**: The evaluator encountered a parser, format, or schema violation and cannot proceed to evaluation (e.g., malformed input context, invalid field types).

**C_local**: The local context state accessible within the current evaluation cycle; one of the three context layers merged into C_rich (see NIP-009).

**C_rich**: The merged context (C_root ∪ C_domain ∪ C_local) before π_safe projection, per NIP-009; immutable within a single evaluation cycle.

**Retry Loop**: A bounded sequence of re-evaluation attempts after an undefined or error outcome.

**Degraded Mode**: A reduced-capability operational state in which the system relaxes non-safety constraints (e.g., slower response, fewer degrees of freedom) to recover from persistent undefined.

**Emergency Stop**: An absolute halt of evaluation and action execution, entered after degraded mode fails to recover.

**Human Escalation**: Transfer of control to a human operator for manual intervention.

**Liveness Metric**: Observed ratio or count of outcomes (e.g., undefined rate, emergency stop frequency) tracked over a time window.

## 4. Specification

### 4.1 Core Safety Invariant

**The following rule is absolute and non-negotiable:**

> If evaluation returns `undefined` or `error`, the Liveness Policy Layer MUST NOT execute or approve any action, regardless of retry state, escalation level, or operational context.

This invariant is the foundation of Noe's safety model. Violation of this invariant is a critical failure.

### 4.2 Evaluation Result Structure

Each evaluation cycle produces a result of the form:

```
result := {
  outcome: 'action' | 'undefined' | 'error',
  value: <action> | null,
  error_type: 'epistemic' | 'context' | 'structural' | null,
  metadata: { timestamp, evaluator_id, context_hash, ... }
}
```

**Outcome Semantics:**

- `outcome == 'action'`: Evaluation succeeded; `value` contains the action.
- `outcome == 'undefined'`: Evaluation did not yield an action; `error_type` distinguishes the cause.
- `outcome == 'error'`: Evaluation encountered a failure condition; `error_type` specifies the category.

### 4.3 State Machine

The Liveness Policy Layer operates as a deterministic state machine:

```
┌─────────────────────────────────────────────────────┐
│                   NOMINAL                            │
│         (evaluation succeeds → action)              │
└──────────────────┬──────────────────────────────────┘
                   │
                   │ undefined or error
                   ▼
┌─────────────────────────────────────────────────────┐
│              RETRY_LOOP                             │
│  (bounded re-evaluation attempts)                   │
└──────────────────┬──────────────────────────────────┘
                   │
        ┌──────────┴──────────┐
        │                     │
     success             retries exhausted
        │                     │
        ▼                     ▼
  (return action)    ┌─────────────────────────────────────────────────────┐
                     │            DEGRADED_MODE                           │
                     │  (relax constraints, reduce DOF, stricter grounding)│
                     └──────────────────┬──────────────────────────────────┘
                                        │
                           ┌────────────┴────────────┐
                           │                        │
                       recovery            timeout / persistent fail
                           │                        │
                           ▼                        ▼
                      (return action)    ┌──────────────────────────────────┐
                                         │       EMERGENCY_STOP            │
                                         │  (halt evaluation & actions)    │
                                         └──────────────────┬───────────────┘
                                                            │
                                                            ▼
                                         ┌──────────────────────────────────┐
                                         │    HUMAN_ESCALATION             │
                                         │  (transfer to operator)          │
                                         └──────────────────────────────────┘
```

**State Transition Rules:**

1. **NOMINAL → RETRY_LOOP**: Triggered immediately upon undefined or error outcome.
2. **RETRY_LOOP → NOMINAL**: Triggered when a retry succeeds (outcome == 'action').
3. **RETRY_LOOP → DEGRADED_MODE**: Triggered when retries are exhausted without success.
4. **DEGRADED_MODE → NOMINAL**: Triggered when evaluation succeeds in degraded mode.
5. **DEGRADED_MODE → EMERGENCY_STOP**: Triggered by timeout or persistent failure.
6. **EMERGENCY_STOP → HUMAN_ESCALATION**: Automatic or triggered by escalation policy.

### 4.4 Required Parameters

All policy implementations MUST define and enforce the following bounded, nonzero parameters:

| Parameter | Type | Semantics | Constraints |
|-----------|------|-----------|-------------|
| `max_retries` | integer | Maximum re-evaluation attempts after undefined/error | ≥ 1; typical: 3–5 |
| `retry_window_ms` | integer | Time window for collecting retry attempts | > 0; typical: 100–1000 ms |
| `undefined_rate_window` | integer | Time window for measuring undefined frequency | > 0; typical: 60000 ms (1 min) |
| `max_undefined_rate` | float | Maximum allowable undefined ratio in window | ∈ [0, 1); typical: 0.1–0.3 |
| `degraded_mode_timeout` | integer | Max duration in degraded mode before emergency stop | > 0; typical: 5000–30000 ms |
| `emergency_stop_timeout` | integer | Max duration in emergency stop before escalation | > 0; typical: 1000–5000 ms |
| `escalation_triggers` | list | Conditions that trigger human escalation | non-empty; e.g., ["persistent_error", "degraded_mode_timeout"] |

### 4.5 Allowed Strategies

#### 4.5.1 Retry

**Conditions:**

- Retry ONLY upon undefined (epistemic or context) or structural error.
- Retry count MUST NOT exceed `max_retries`.
- Retry attempts MUST occur within `retry_window_ms`.

**Actions:**

- **Epistemic Undefined**: Request fresh sensor data; rebuild C_local if needed.
- **Context Undefined**: Refresh or reconstruct C_local from authoritative sources.
- **Structural Error**: Validate and repair input context; resubmit for evaluation.

**Determinism:** Retries MUST NOT alter C_rich or falsify context. Each retry uses the same C_rich and fresh C_local snapshots.

#### 4.5.2 Degraded Mode

**Entry:** Retries exhausted; undefined outcome persists.

**Actions:**

- Reduce operational speed (e.g., increase decision latency to allow additional sensor sampling).
- Reduce degrees of freedom (e.g., constrain action space to conservative options).
- Increase grounding requirements (e.g., require stronger evidence thresholds).

**Exit Conditions:**

- Evaluation succeeds (outcome == 'action') → return to NOMINAL.
- Timeout expires (`degraded_mode_timeout`) → transition to EMERGENCY_STOP.

#### 4.5.3 Safe Fallback

In degraded mode, a system MAY employ safe fallback actions:

- **Hold**: Maintain current state; do not advance.
- **Retreat**: Return to a known-safe state.

Safe fallbacks MUST be explicitly pre-authorized and unambiguous. They are NOT replacements for undefined→action; they are explicit policies in degraded mode only.

> **WARNING — Application-Layer Boundary**: Safe fallback actions are decisions made by the application's policy layer, entirely independent of the Noe evaluator. The evaluator's output remains `undefined`; the policy layer decides what the *system* does in response. A conforming implementation MUST NOT represent a safe fallback as an action derived from an undefined evaluation result. The fallback is the application's choice, not Noe's conclusion.

#### 4.5.4 Emergency Stop

**Entry:** Degraded mode timeout expires or escalation trigger is met.

**Action:** Halt all evaluation and action execution immediately.

**Duration:** MUST NOT remain in emergency stop indefinitely; transition to human escalation within `emergency_stop_timeout`.

#### 4.5.5 Human Escalation

**Entry:** Emergency stop timeout expires or explicit escalation condition is triggered.

**Action:** Transfer full context and decision history to a human operator.

**Operator Responsibilities:** The human operator MUST review the evaluation history, understand the failure mode, and explicitly authorize recovery or shutdown.

### 4.6 Prohibited Behaviors

Implementations MUST NOT:

1. **Execute on undefined/error**: Attempt to derive or force an action from an undefined or error result.
2. **Treat undefined as permissive**: Assume undefined means "any action is safe"; undefined means "no action is safe".
3. **Reuse previous actions**: Resubmit or replay a stale action when current evaluation fails.
4. **Retry indefinitely**: Exceed `max_retries` or violate `retry_window_ms`.
5. **Alter C_rich**: Falsify or modify the total context to force a different evaluation result.
6. **Ignore staleness**: Proceed with stale C_local without attempting refresh.
7. **Mask structural errors**: Treat format errors as epistemic undefined; escalate structural errors.
8. **Bypass undefined→non-execution**: Skip the safety check or apply loopholes.

### 4.7 Responsibility Matrix

| Responsibility | Owner | Requirement |
|---|---|---|
| Enforce safety invariant | Liveness Policy Layer | undefined/error → MUST NOT execute action |
| Distinguish undefined types | Evaluator & Policy Layer | Classify as epistemic, context, or structural |
| Bound retries | Policy Layer | max_retries & retry_window_ms enforced |
| Handle degraded mode | Policy Layer | Implement reduced-DOF fallback |
| Implement emergency stop | Policy Layer | Halt evaluation & actions on timeout |
| Provide escalation | Policy Layer | Human escalation with full context |
| Log transitions | Policy Layer | Record state changes per NIP-010 |
| Maintain determinism | Evaluator & Policy Layer | No falsified context or C_rich modification |

### 4.8 Liveness Metrics

Implementations SHOULD track the following metrics over rolling time windows:

| Metric | Definition | Unit | Recommended Target |
|--------|------------|------|-------------------|
| `p_emergency_stop` | Probability of entering emergency stop | ratio | ≤ 0.01 (≤1% of cycles) |
| `p_degraded_mode` | Probability of entering degraded mode | ratio | ≤ 0.05 (≤5% of cycles) |
| `p_undefined` | Probability of undefined outcome | ratio | ≤ 0.1 (≤10% of cycles) |
| `mtbf_stop` | Mean time between failures (emergency stop) | milliseconds | ≥ 600,000 (≥10 min) |

These targets are **informative and context-dependent**. Operators MUST adjust thresholds based on deployment criticality and tolerance.

### 4.9 Reference Pseudocode

```python
class NoePolicyWrapper:
    def __init__(self, evaluator, max_retries=3, retry_window_ms=500,
                 undefined_rate_window=60000, max_undefined_rate=0.1,
                 degraded_mode_timeout=10000, emergency_stop_timeout=5000):
        self.evaluator = evaluator
        self.max_retries = max_retries
        self.retry_window_ms = retry_window_ms
        self.undefined_rate_window = undefined_rate_window
        self.max_undefined_rate = max_undefined_rate
        self.degraded_mode_timeout = degraded_mode_timeout
        self.emergency_stop_timeout = emergency_stop_timeout

        self.state = 'NOMINAL'
        self.undefined_history = []  # (timestamp, type) tuples
        self.degraded_mode_entry_time = None
        self.emergency_stop_entry_time = None

    def evaluate(self, context):
        """Main entry point for evaluation."""
        if self.state == 'EMERGENCY_STOP':
            if self._emergency_stop_timeout_exceeded():
                self._transition_to('HUMAN_ESCALATION')
                return {'outcome': 'escalation', 'context': context}
            else:
                return {'outcome': 'emergency_stop', 'value': None}

        if self.state == 'DEGRADED_MODE':
            if self._degraded_mode_timeout_exceeded():
                self._transition_to('EMERGENCY_STOP')
                return self.evaluate(context)  # Re-enter to handle emergency stop
            result = self._evaluate_in_degraded_mode(context)
            if result['outcome'] == 'action':
                self._transition_to('NOMINAL')
            return result

        # NOMINAL mode: attempt evaluation
        result = self.evaluator.evaluate(context)

        if result['outcome'] == 'action':
            # Success
            self._record(result)
            return result
        else:
            # undefined or error
            self._record(result)
            return self._handle_failure(result, context)

    def _handle_failure(self, result, context):
        """Handle undefined or error outcome."""
        self._transition_to('RETRY_LOOP')
        retry_start = now_ms()

        for attempt in range(1, self.max_retries + 1):
            if now_ms() - retry_start > self.retry_window_ms:
                break  # retry window exceeded; fall through to degraded/emergency

            retry_result = self._retry_once(result, context)
            self._record(retry_result)

            if retry_result['outcome'] == 'action':
                self._transition_to('NOMINAL')
                return retry_result

        # All retries exhausted
        if self._too_many_undefined():
            self._transition_to('EMERGENCY_STOP')
            return {'outcome': 'emergency_stop', 'value': None}
        else:
            self._transition_to('DEGRADED_MODE')
            self.degraded_mode_entry_time = now_ms()
            return self._evaluate_in_degraded_mode(context)

    def _retry_once(self, result, context):
        """Perform a single retry."""
        error_type = result.get('error_type')

        if error_type == 'epistemic':
            # Request fresh sensor data
            context = self._refresh_sensors(context)
        elif error_type == 'context':
            # Rebuild C_local
            context = self._rebuild_context(context)
        elif error_type == 'structural':
            # Validate and repair
            context = self._validate_and_repair(context)

        return self.evaluator.evaluate(context)

    def _evaluate_in_degraded_mode(self, context):
        """Evaluation with reduced DOF and stricter grounding."""
        degraded_context = self._apply_degraded_constraints(context)
        result = self.evaluator.evaluate(degraded_context)
        result['state'] = 'degraded_mode'
        return result

    def _too_many_undefined(self):
        """Check if undefined rate exceeds threshold."""
        now = now_ms()
        window_start = now - self.undefined_rate_window

        recent_undefined = [
            t for t, _ in self.undefined_history
            if t >= window_start
        ]

        total_evaluations = self._count_evaluations_in_window(window_start)
        if total_evaluations == 0:
            return False

        rate = len(recent_undefined) / total_evaluations  # ratio ∈ [0, 1)
        return rate > self.max_undefined_rate

    def _record(self, result):
        """Record result and update metrics."""
        if result['outcome'] in ['undefined', 'error']:
            error_type = result.get('error_type', 'unknown')
            self.undefined_history.append((now_ms(), error_type))

    def _transition_to(self, new_state):
        """Record state transition (per NIP-010)."""
        old_state = self.state
        self.state = new_state
        self._log_transition(old_state, new_state, timestamp=now_ms())

    def _log_transition(self, old_state, new_state, timestamp):
        """Log state transition for auditing."""
        # Implementation per NIP-010 (audit logging, trace serialization)
        pass

    def _emergency_stop_timeout_exceeded(self):
        """Check if emergency stop timeout has expired."""
        if self.emergency_stop_entry_time is None:
            self.emergency_stop_entry_time = now_ms()
        return now_ms() - self.emergency_stop_entry_time > self.emergency_stop_timeout

    def _degraded_mode_timeout_exceeded(self):
        """Check if degraded mode timeout has expired."""
        if self.degraded_mode_entry_time is None:
            return False
        return now_ms() - self.degraded_mode_entry_time > self.degraded_mode_timeout

    def _refresh_sensors(self, context):
        """Refresh sensor data in context."""
        # Implementation-specific
        return context

    def _rebuild_context(self, context):
        """Rebuild local context from authoritative sources."""
        # Implementation-specific
        return context

    def _validate_and_repair(self, context):
        """Validate and repair structural issues."""
        # Implementation-specific
        return context

    def _count_evaluations_in_window(self, window_start):
        """Return total evaluation count (success + undefined + error) since window_start."""
        # Implementation-specific: must track all outcomes, not just undefined.
        # A conforming implementation maintains a ring buffer or counter of all
        # evaluation timestamps and returns the count within the window.
        raise NotImplementedError

    def _apply_degraded_constraints(self, context):
        """Apply reduced-DOF constraints for degraded mode."""
```

## 5. Rationale

### 5.1 Why the Core Safety Invariant Is Absolute

Noe's threat model requires that no undefined or error outcome can produce an unintended action. This is analogous to fail-safe design in safety-critical systems: when in doubt, do not act. Any violation of this invariant, even under exceptional circumstances, breaks the safety model and must be treated as a critical failure.

### 5.2 Why Distinguish Undefined Types

Not all undefined outcomes are equal:

- **Epistemic undefined**: May resolve with fresh data; retry is appropriate.
- **Context undefined**: Requires local context refresh; retry is appropriate.
- **Structural error**: Indicates malformed input; escalate rather than retry indefinitely.

By distinguishing these, the policy layer can apply targeted recovery strategies instead of generic retry-everything logic.

### 5.3 Why Bounds Are Mandatory

Unbounded retries, infinite degraded mode, or open-ended emergency stops create the risk of:

- Resource exhaustion.
- Cascading failures.
- Hidden dependency on external services that may never recover.

Explicit bounds force explicit trade-offs between recovery attempts and operational resilience.

### 5.4 Why Determinism Must Be Maintained

Retrying with altered C_rich or falsified context would defeat the purpose of deterministic evaluation. If the evaluation is truly deterministic, the same C_rich + C_local combination will always produce the same result. Changing C_rich breaks this invariant and hides the true reason for the failure.

### 5.5 Why Degraded Mode Exists

Some systems cannot afford an immediate emergency stop when a transient undefined occurs. Degraded mode allows the system to relax non-safety constraints (e.g., increase latency, reduce DOF) to buy time for recovery without violating the core safety invariant.

### 5.6 Why Hysteresis Is Permitted (With Caveats)

A system MAY apply deterministic hysteresis to avoid thrashing between states (e.g., require 2 consecutive successes to exit degraded mode). However, this hysteresis MUST NOT:

- Create evidence that "undefined leads to action" under any interpretation.
- Bypass the undefined→non-execution rule.

## 6. Examples

### 6.1 Example A: Single Undefined Recovery

**Scenario**: A sensor is briefly unavailable; the evaluator returns epistemic undefined on cycle N. A retry with fresh sensor data on cycle N+1 succeeds.

**Policy Behavior:**

1. Cycle N: Evaluation → undefined (epistemic).
2. Policy: NOMINAL → RETRY_LOOP.
3. Retry N+1: Refresh sensors; evaluate again.
4. Cycle N+1: Evaluation → action.
5. Policy: RETRY_LOOP → NOMINAL.

**Outcome**: No action on cycle N; normal action on cycle N+1.

### 6.2 Example B: Persistent Undefined → Emergency Stop

**Scenario**: Context is stale or corrupted; the evaluator consistently returns context undefined despite retry attempts. After `max_retries`, the policy layer detects a high undefined rate and transitions to degraded mode. Degraded mode timeout expires without recovery.

**Policy Behavior:**

1. Cycle 1–3: Retries exhausted; undefined rate exceeds threshold.
2. Policy: RETRY_LOOP → DEGRADED_MODE.
3. Degraded mode cycles: Stricter grounding, no action produced.
4. Timeout expires.
5. Policy: DEGRADED_MODE → EMERGENCY_STOP.
6. Emergency stop duration: System halted; no further evaluation.
7. Emergency stop timeout expires.
8. Policy: EMERGENCY_STOP → HUMAN_ESCALATION.

**Outcome**: No action executed; human operator takes over.

### 6.3 Example C: Structural Error → Escalation

**Scenario**: Input context has a malformed field (e.g., invalid JSON or schema violation). The evaluator returns structural error. A retry attempt to repair the context fails. Policy escalates.

**Policy Behavior:**

1. Cycle 1: Evaluation → error (structural).
2. Policy: NOMINAL → RETRY_LOOP.
3. Retry: Attempt to validate/repair context.
4. Cycle 2: Evaluation → error (structural) again.
5. Policy: RETRY_LOOP → EMERGENCY_STOP (escalation trigger triggered).
6. Policy: EMERGENCY_STOP → HUMAN_ESCALATION immediately.

**Outcome**: Structural error surfaced to human operator; no action executed.

## 7. Conformance Requirements

An implementation conforms to NIP-016 if and only if it:

1. **Enforces the Core Safety Invariant**: No action is executed on undefined or error.
2. **Implements the State Machine**: Transitions between NOMINAL, RETRY_LOOP, DEGRADED_MODE, EMERGENCY_STOP, and HUMAN_ESCALATION as specified.
3. **Defines All Required Parameters**: `max_retries`, `retry_window_ms`, `undefined_rate_window`, `max_undefined_rate`, `degraded_mode_timeout`, `emergency_stop_timeout`, `escalation_triggers` are all present and bounded.
4. **Distinguishes Undefined Types**: Classifies failures as epistemic, context, or structural and applies appropriate recovery.
5. **Bounds All Loops**: Retries, degraded mode, and emergency stop durations are finite and enforced.
6. **Prohibits Forbidden Behaviors**: Does not execute on undefined, reuse stale actions, alter C_rich, or mask errors.
7. **Logs Transitions**: Records all state transitions per NIP-010.
8. **Maintains Determinism**: Does not falsify context or alter C_rich during retries.

---

## 8. Backwards Compatibility

NIP-016 does not modify the Noe evaluation interface or outcome format. Existing evaluators that produce `{outcome, value, error_type}` results are compatible.

However, adopting NIP-016 DOES change system behavior:

- Systems previously executing on undefined now halt or escalate.
- Retry logic replaces immediate escalation for transient failures.
- Undefined rate monitoring may reveal previously hidden failure patterns.

Operators MUST review and adjust parameters when upgrading to NIP-016 implementations.

## 9. Security and Safety Considerations

### 9.1 Safety Invariant Violation

**Risk**: A buggy implementation executes an action on undefined.

**Mitigation**:

- Implement the safety check as a guard clause that triggers before any action submission.
- Use immutable result structures to prevent in-place modifications.
- Log every undefined/error outcome and every non-execution decision.
- Audit logs regularly to detect violations.

### 9.2 Retry Amplification

**Risk**: Retries cause load spikes or resource exhaustion.

**Mitigation**:

- Set `max_retries` and `retry_window_ms` conservatively.
- Implement backoff (exponential or random jitter) between retries.
- Monitor retry frequency; escalate if it exceeds expected baseline.

### 9.3 Stale Context Exploitation

**Risk**: An adversary exploits stale C_local to induce undefined, then escalate.

**Mitigation**:

- Require explicit timestamp validation for all context data.
- Reject context older than a pre-defined staleness threshold.
- Log and alert on frequent context staleness events.

### 9.4 Structural Error Masking

**Risk**: Structural errors are misclassified as epistemic undefined to avoid escalation.

**Mitigation**:

- Implement strict schema validation; fail-fast on format errors.
- Distinguish parser errors from evaluation uncertainty.
- Audit error classifications; require justification for reclassification.

### 9.5 Hysteresis Side Channels

**Risk**: Hysteresis logic creates observable patterns that leak information about internal state.

**Mitigation**:

- Document hysteresis rules explicitly.
- Ensure hysteresis does not create evidence of undefined→action causality.
- Verify that hysteresis only affects timing, not safety.

### 9.6 Emergency Stop Reliability

**Risk**: Emergency stop is not reliable (e.g., system continues to execute actions).

**Mitigation**:

- Implement emergency stop as a hard interrupt in the action execution pipeline.
- Test emergency stop under load and failure conditions.
- Ensure escalation channel is monitored and responsive.
