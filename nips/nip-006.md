# NIP-006: Scalar and Intensity Operators

## Abstract

This document specifies three scalar intensity operators for the Noe language that modify the magnitude of semantic content without altering truth values. The operators apply multiplicative scaling factors (0.5x, 1.0x, 2.0x) representing diminished, neutral, and amplified intensity respectively. These Tier-1 postfix operators integrate into the language grammar at a precise point in the resolution order and enforce strict domain restrictions to maintain semantic coherence across valid attachment targets.

## Notation Convention

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in BCP 14 [RFC 2119] [RFC 8174] when, and only when, they appear in ALL CAPITALS, as shown here.

## 1. Purpose

The scalar intensity operators provide a mechanism for speakers to modulate the magnitude or degree of semantic concepts without affecting their truth values. Each operator applies a multiplicative factor to the scalar magnitude of its target, enabling fine-grained expression of intensity across multiple modalities while maintaining the principle that intensity modifications are orthogonal to semantic truth.

## 2. Scope

### 2.1 In Scope

- Definition and specification of three scalar intensity operators (', ", °)
- Multiplicative scaling factors {0.5x, 1.0x, 2.0x} representing diminished, neutral, and amplified intensity
- Valid attachment domains: valence roots, sensory roots, Tier-1 quality roots, comparative constructs, and mek-derived quality actions
- Grammar integration as postfix operators
- Resolution ordering and precedence rules
- Multimodal distinctiveness requirements
- Registry format for intensity operator entries
- Evaluation semantics and domain enforcement

### 2.2 Out of Scope

- Definition of additional scaling factors or operators
- Modification of core morphological or grammatical systems
- Interaction with truth-value operators or logical connectives
- Semantic interpretation beyond scalar magnitude modification

## 3. Definitions

**Scalar Magnitude**: A numeric value representing the degree or intensity of a semantic concept, independent of truth value. Intensity operators modify this value multiplicatively.

**Intensity Operator**: A unary postfix operator that applies a multiplicative scaling factor to the scalar magnitude of an attached atom.

**Valence Root**: A root expressing relational or action semantics (fel, dar, nem, zar, vai as specified in NIP-002).

**Sensory Root**: A root expressing perception or sensory modalities (vis, hau, per as specified in NIP-002).

**Tier-1 Quality Root**: A root classified as Q-class quality in NIP-002 that belongs to the first implementation tier.

**Comparative Construct**: An expression using comparative scalar operators (mor, les) as defined in the Registry V1.1.0 Amendment. These binary operators compare scalar magnitudes of intensity-bearing expressions and return truth values. See `registry_v1.1_amendment.md` for formal semantics.

**mek-derived Quality Action**: A quality concept produced through mek morphological derivation as specified in NIP-003.

**Baseline Intensity**: The implicit multiplicative factor 1.0x applied when no intensity operator is present. This is equivalent to the neutral operator " (double-quote).

**Domain Restriction**: A constraint limiting the application of intensity operators to specific semantic classes of atoms.

## 4. Specification

### 4.1 Operator Table

| Glyph | Phonetic | Multiplier | Intensity Level |
|-------|----------|------------|-----------------|
| ' | -a | 0.5x | Diminished |
| " | -u | 1.0x | Neutral / Baseline |
| ° | -o | 2.0x | Amplified |

Phonetic forms are appended as suffixes to the phonetic form of the target atom (e.g., `fel'` is spoken as "fel-a", `fel°` as "fel-o"). The three vowel suffixes (-a, -u, -o) are chosen for maximal phonemic distinctiveness in spoken, subvocalized, haptic, and BCI contexts. The phonetic form encodes operator identity, not the underlying multiplier value.

Intensity operators are syntactic modifiers, not registry glyphs. They do not appear in the glyph registry and have no glyph ID or domain classification. Their phonetic forms, visual forms, and multiplicative semantics are defined entirely by this specification and their implementation in the parser grammar.

### 4.2 Attachment Domain Restrictions

Intensity operators MUST attach only to the following atom types:

1. Valence roots (fel, dar, nem, zar, vai)
2. Sensory roots (vis, hau, per)
3. Tier-1 quality roots (Q-class)
4. Comparative constructs (mor, les) — *see Registry V1.1.0 Amendment*
5. Mek-derived quality actions

Intensity operators MUST NOT attach to:

- Structural constants
- Logical operators
- Quantifiers
- Numeric atoms
- Demonstratives
- Entities
- Spatial roots
- Morphology operators
- Fused compounds
- Literals

### 4.3 Grammar Integration

The atom production rule in the Noe grammar is extended with an optional scalar modifier:

```
atom := base_atom [ScalarMod]
ScalarMod := "'" | '"' | '°'
```

Intensity operators bind with higher precedence than all other postfix operators except morphological operators.

### 4.4 Resolution Order

The complete resolution order for operator precedence is:

1. Fusion
2. Inversion
3. Nominalizers
4. Verbalizer
5. Intensity
6. Grammar

Intensity modifiers are applied AFTER all morphological operations (NIP-003) and BEFORE grammar operations (NIP-004).

### 4.5 Baseline Intensity

The absence of an intensity marker implies a baseline multiplicative factor of 1.0x, identical to the explicit " (double-quote) operator. This baseline applies uniformly across all valid attachment domains. The scalar magnitude of an unmodified atom is its intrinsic value multiplied by 1.0.

### 4.6 Semantic Behavior

Intensity operators apply a multiplicative scaling factor to the scalar magnitude of a semantic concept. They do not affect truth values. An expression with an intensity operator and its unmodified counterpart yield identical truth values under all evaluations. If the operand is `undefined`, the result is `undefined` (undefined propagation).

The multiplicative model computes the output scalar as:

```
output_scalar = intrinsic_value * multiplier
```

where `multiplier` is 0.5 for ', 1.0 for ", or 2.0 for °.

Example: `hum es fel°` and `hum es fel` carry the same truth conditions but differ in intensity magnitude. If `fel` has intrinsic scalar 0.7, then `fel°` yields scalar 1.4 while `fel'` yields scalar 0.35.

Invalid domain attachments produce an undefined value at the evaluation phase. The grammar layer accepts any atom with an intensity modifier; semantic enforcement occurs at the evaluator layer.

### 4.7 Stacking Prohibition

Multiple intensity operators MUST NOT be applied to a single atom. Only one intensity operator per atom is permitted.

### 4.8 Multimodal Distinctiveness

Intensity operators MUST be visually, phonemically, haptically, and BCI-distinctively different from one another. This requirement ensures accessibility across all supported modalities:

- **Visual**: Distinct glyph forms (', ", °)
- **Phonemic**: Distinct vowel suffixes (-a, -u, -o)
- **Haptic**: Distinct tactile patterns
- **BCI**: Distinct neural signatures

## 5. Rationale

### 5.1 Scalar Independence

Intensity operators are designed to be orthogonal to truth values. In formal semantics, a proposition remains true or false regardless of intensity modification. This design prevents category confusion between magnitude and truth.

### 5.2 Domain Restrictions

Domain restrictions are enforced at the semantic evaluation layer rather than the grammar layer. This separation of concerns allows the parser to accept broader input while semantic validation occurs during evaluation. Domain checks occur only when intensity modifiers are present, reducing computational overhead for unmodified atoms.

### 5.3 Baseline Value

The selection of 1.0x as the baseline multiplier means that an unmodified atom retains its intrinsic scalar value without alteration. The diminished operator (0.5x) halves the magnitude while the amplified operator (2.0x) doubles it, providing a symmetric logarithmic scale around the neutral point. Implicit baseline assignment eliminates the need for explicit marking on the majority of atoms.

### 5.4 Resolution Order

Intensity operators are positioned in the resolution order after morphology but before grammar integration. This placement ensures that intensity applies to fully morphologically analyzed forms while remaining available to grammar operations that may reference scalar values.

### 5.5 Multimodal Design

The requirement for multimodal distinctiveness ensures that Noe expressions remain unambiguous across visual, auditory, haptic, and BCI channels. The selection of ASCII-range characters (', ", °) for the operator glyphs maximizes compatibility with existing parser infrastructure and keyboard layouts.

### 5.6 Multiplicative Model

The multiplicative model was chosen over an absolute-value model for several reasons. First, it preserves the intrinsic scalar semantics of the target atom: a diminished strong signal remains stronger than an amplified weak signal. Second, the logarithmically symmetric scale (0.5x, 1.0x, 2.0x) provides equal perceptual steps in each direction from neutral. Third, the 1.0x baseline means that omitting the operator produces no alteration, a desirable identity property.

## 6. Examples

### 6.1 Valid Applications

Intensity operator applied to a valence root:

```noe
dar'  "dar-a"  (diminished action, scalar × 0.5)
dar"  "dar-u"  (baseline action, scalar × 1.0)
dar°  "dar-o"  (amplified action, scalar × 2.0)
```

Intensity operator applied to a sensory root:

```noe
vis'  "vis-a"  (dim or faint sight, scalar × 0.5)
vis"  "vis-u"  (normal sight, scalar × 1.0)
vis°  "vis-o"  (bright or sharp sight, scalar × 2.0)
```

Intensity operator applied to a Tier-1 quality root:

```noe
kel'  "kel-a"  (slightly cold, scalar × 0.5)
kel"  "kel-u"  (moderately cold, scalar × 1.0)
kel°  "kel-o"  (extremely cold, scalar × 2.0)
```

Intensity operator applied to a comparative construct (mor/les added in Registry V1.1.0):

```noe
mor'  "mor-a"  (slightly more, scalar × 0.5)
mor°  "mor-o"  (much more, scalar × 2.0)
```

### 6.2 Invalid Applications

Attempting to attach intensity to structural constants:

```noe
es°  (ERROR: cannot modify structural constant)
```

Attempting to attach intensity to logical operators:

```noe
neg' (ERROR: cannot modify logical operator)
```

Attempting to attach intensity to quantifiers:

```noe
ket° (ERROR: cannot modify quantifier)
```

### 6.3 Semantic Equivalence

The following pairs have identical truth conditions but differ in intensity:

```noe
hum es fel° ≡truth hum es fel    (scalar × 2.0 vs × 1.0)

per vis'   ≡truth per vis        (scalar × 0.5 vs × 1.0)

zar kel"   ≡truth zar kel        (scalar × 1.0 vs × 1.0, identical)
```

Truth equivalence does not imply intensity equivalence; the scalar magnitudes differ while truth values remain identical.

## 7. Conformance Requirements

Implementations of Noe MUST:

- Support all three scalar intensity operators (', ", °)
- Apply the specified multiplicative factors (0.5x, 1.0x, 2.0x) to the scalar magnitude of the target atom
- Propagate undefined if the operand is undefined
- Enforce domain restrictions at the evaluation layer
- Assign baseline intensity (1.0x) when no operator is present
- Prevent stacking of multiple intensity operators on a single atom
- Maintain multimodal distinctiveness across visual, phonemic, haptic, and BCI modalities
- Process intensity operators in the correct resolution order (after morphology, before grammar)
- Return undefined for invalid domain attachments

Implementations SHOULD:

- Provide clear error messages when invalid intensity attachments are detected
- Support user configuration for the visual representation of intensity operators
- Log intensity modification events for debugging and analysis

## 8. Backwards Compatibility

This specification introduces new functionality and does not modify existing Noe semantics. Atoms without intensity operators continue to behave identically to prior implementations. The addition of optional intensity markers is backward-compatible with NIPs 1 through 5.

## 9. Security and Safety Considerations

### 9.1 Semantic Clarity

Intensity operators do not introduce ambiguity into truth values. Users must understand that intensity modification is distinct from truth modification. Documentation and educational materials SHOULD emphasize this distinction.

### 9.2 Domain Enforcement

Domain restrictions prevent misapplication of intensity operators to structural or logical elements where they would be semantically meaningless. Enforcement at the evaluation layer ensures that invalid applications are caught during execution rather than silently ignored.

### 9.3 Multimodal Security

The requirement for multimodal distinctiveness prevents confusion between intensity levels across different input modalities. This is particularly important for BCI implementations where neural signal distinctiveness is critical for reliable interpretation.
